# RAG-прототип: дизайн

Дата: 23.11.2026

## Зачем

Учебный пет-проект: разобраться в механике RAG не по статьям, а руками —
и получить воспроизводимый пример с понятными компромиссами: чанкинг,
эмбеддинги, поиск, промпт, оценка качества.

## Что делаем

CLI-прототип на Python: задаёшь вопрос — получаешь ответ по базе из 10 статей
Википедии (REST, JWT, Kafka, PostgreSQL, микросервисы, Kubernetes, BPMN,
системный анализ, OpenAPI, UML). Всё локально, без платных API.

## Чего не делаем

Веб-интерфейс, загрузка PDF, авторизация, продакшн-инфраструктура, оценка через
RAGAS. Это следующие шаги, если захочется.

## Подходы

- **A. Ручной RAG на стандартных средствах (выбран).** Ollama даёт и эмбеддинги,
  и генерацию; поиск — косинусное сходство на numpy; индекс — JSON. Зависимостей
  почти нет, вся механика видна. Минус: не похоже на промышленный стек.
- **B. Chroma + sentence-transformers.** Ближе к индустрии, но тянет torch
  (гигабайты) на Intel Mac и прячет механику за библиотекой. Как второй шаг —
  полезно, как первый — мешает пониманию.

## Принятые решения

- Генерация: `qwen2.5:3b-instruct` через Ollama (1.9 ГБ, бесплатно).
  `qwen3:4b` тоже осталась в системе, но минутами «рассуждает» перед ответом —
  для интерактивного прототипа не подходит.
- Эмбеддинги: `nomic-embed-text` через Ollama (~275 МБ).
- Чанкинг: по абзацам, ориентир 800 символов, перекрытие 150, с сохранением
  названия статьи и номера чанка.
- Поиск: гибрид — косинусное сходство (смысл) + BM25 (слова), top-6 чанков.
  Чистый векторный поиск промахивался на вопросах-перечислениях.
- Ответ: только по найденному контексту, с указанием источников; если лучший
  score ниже порога — честное «в документах нет».
- Код и документация на русском, имена файлов латиницей.

## Файлы

```
DESIGN.md                  этот документ
README.md                  схема, запуск, ограничения
LICENSE                    MIT
requirements.txt           requests, numpy
.gitignore                 окружение, данные, индекс
fetch_data.py              скачивание статей из Википедии
data/                      скачанные статьи (.txt)
build_index.py             нарезка + эмбеддинги -> index.json
ollama_client.py           обёртка над Ollama: эмбеддинги и генерация
retrieval.py               гибридный поиск: вектор + BM25, top-6
ask.py                     вопрос -> поиск -> ответ с источниками
eval.py                    прогон 10 контрольных вопросов и 3 ловушек
eval_results.md            отчёт прогона (создаётся автоматически)
```

## Критерии готовности

1. `python ask.py "..."` отвечает по статьям и показывает источники.
2. На вопрос вне базы отвечает «в документах нет».
3. Не меньше 8 из 10 контрольных вопросов — корректный ответ.
4. Автор может своими словами объяснить каждый шаг и его trade-off.

## Результат

- правильных ответов — 9 из 10;
- честных отказов на вопросах вне базы — 3 из 3;
- после замены чистого векторного поиска на гибрид качество выросло с 7/10
  до 9/10: нужный абзац BPMN поднялся с 39-го места на 5-е, Kafka — с 12-го
  на 3-е.

## Шаги (после каждого — стоп и проверка)

1. Окружение и корпус: venv, зависимости, статьи и embedding-модель.
2. Индекс: нарезка, эмбеддинги, `index.json`; пример чанка.
3. Ответ: поиск, промпт, источники; проверка на нескольких вопросах.
4. Оценка: 10 контрольных вопросов, разбор провалов, улучшение поиска.
5. README и итоговый отчёт.

## Допущения

- Интернет есть, можно скачать ~300 МБ.
- Python 3.9+ достаточно; зависимости ставятся в venv.
- Статьи и вопросы на русском.
- Общее время: 2–3 часа вместе с разборами.
