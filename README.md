# RAG-прототип на Python

[![Python](https://img.shields.io/badge/Python-3.9%2B-3776AB?logo=python&logoColor=white)](https://www.python.org/)
[![License](https://img.shields.io/badge/license-MIT-green)](LICENSE)

**EN:** A local RAG prototype over 10 articles: paragraph-aware chunking,
embeddings, hybrid retrieval (cosine + BM25), citations and honest refusals.
Evaluation is reproducible: 9/10 correct answers, 3/3 refusals on out-of-domain
questions. Runs entirely on Ollama, no paid APIs.

Пет-проект: чат по базе знаний из 10 статей. Всё работает локально — Ollama,
эмбеддинги `nomic-embed-text` и генератор `qwen2.5:3b-instruct`. Платные API
не нужны.

Главная ценность — не «ещё один чат с документами», а прозрачная механика:
видно, как текст режется на чанки, как считается сходство, где поиск
промахивается и как это измеряется и чинится.

## Что здесь можно посмотреть

- полный цикл RAG: подготовка данных → чанкинг → эмбеддинги → поиск →
  промпт → ответ → оценка;
- гибридный поиск: косинусное сходство плюс BM25, а не только векторы;
- воспроизводимая оценка: 10 контрольных вопросов с эталонами и 3 ловушки;
- разбор реальных провалов: почему качество выросло с 7/10 до 9/10.

| Проверка | Результат |
|---|---|
| Правильных ответов | **9 из 10** |

## Схема

```
Индексация (один раз):
data/*.txt → абзацы → чанки 800/150 → эмбеддинги → index.json

Ответ (на каждый вопрос):
вопрос → эмбеддинг → гибридный поиск (вектор + BM25) → top-6
       → промпт с фрагментами → qwen2.5:3b → ответ + источники
```

## Быстрый старт

Нужны Python 3.9+ и [Ollama](https://ollama.com). Модели скачиваются один раз.

```bash
git clone https://github.com/kabanovsv/rag-prototype.git
cd rag-prototype

# 1. Окружение
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 2. Модели
ollama pull nomic-embed-text
ollama pull qwen2.5:3b-instruct

# 3. Данные и индекс (2–3 минуты)
.venv/bin/python fetch_data.py
.venv/bin/python build_index.py

# 4. Вопрос
.venv/bin/python ask.py "Что такое JWT?"
```

Полезные команды:

```bash
# показать промпт, который получает модель
.venv/bin/python ask.py "Что такое BPMN?" --show-prompt

# прогнать контрольные вопросы (около 4 минут)
.venv/bin/python eval.py
```

## Как это работает

### 1. Индексация

- `fetch_data.py` скачивает 10 статей по темам: интеграции, данные,
  архитектура, анализ (REST, JWT, Kafka, PostgreSQL, микросервисы,
  Kubernetes, BPMN, системный анализ, OpenAPI, UML).
- `build_index.py` режет текст на абзацы. Абзац длиннее 648 символов делится
  на предложения. Затем абзацы собираются в чанки до 800 символов; каждый
  следующий начинается с хвоста предыдущего (перекрытие ~150 символов,
  обрезка по границе слова).
- Каждый чанк превращается в вектор из 768 чисел моделью `nomic-embed-text`.
  У документов и вопросов разные префиксы (`search_document:` /
  `search_query:`) — так модель обучена.
- Результат: `index.json`, 188 чанков, около 2 МБ.

### 2. Поиск

Гибрид, 50 на 50:

- **Векторы.** Вопрос и чанки нормализуются, близость — косинусное сходство
  (скалярное произведение нормированных векторов).
- **BM25.** Классическая поисковая оценка по словам: слово весит тем больше,
  чем реже оно встречается в базе и чаще — в конкретном чанке. Слова грубо
  стеммируются обрезкой до 5 букв.
- Обе оценки приводятся к диапазону 0–1, складываются с весами 0,5/0,5,
  берутся 6 лучших чанков.

Чистый векторный поиск промахивался на вопросах-перечислениях: нужный абзац
оказывался на 39-м месте из 188. Гибрид поднял его на 5-е.

### 3. Ответ

- Порог: если лучшее косинусное сходство ниже 0,70, модель не вызывается —
  сразу честный отказ.
- Промпт требует отвечать только по фрагментам, не выдумывать факты и
  ссылаться на номера фрагментов.
- Генерация с `temperature: 0` и лимитом 400 токенов.
- После ответа печатается список источников с их оценками.

## Настройки

| Параметр | Где | Значение | На что влияет |
|---|---|---|---|
| `CHUNK_SIZE` | `build_index.py` | 800 | Размер чанка: крупнее — больше контекста, но шума |
| `OVERLAP` | `build_index.py` | 150 | Сколько символов повторяется на стыке |
| `TOP_K` | `retrieval.py` | 6 | Сколько фрагментов получает модель |
| `VECTOR_WEIGHT` | `retrieval.py` | 0.5 | Баланс «смысл / слова» |
| `MIN_SCORE` | `ask.py` | 0.70 | Грубый порог отказа по косинусу |
| `LLM_MODEL` | `ollama_client.py` | `qwen2.5:3b-instruct` | Генератор ответа |

## Ограничения

- База маленькая (188 чанков), индекс — обычный JSON, поиск перебором.
  Для тысяч документов нужна векторная БД.
- Вопросы «перечисли всё» решаются плохо: один top-6 не покрывает статью
  целиком. Нужно разбиение вопроса или больший контекст.
- Автоматическая проверка по ключевым словам ошибается: ответ про PostgreSQL
  назвал репликацию, но не EXPLAIN, и засчитан как провал.
- Модель 3B иногда путает детали. Это ограничение генератора, а не поиска.
- Нет доступа по ролям, версионирования документов и инкрементального индекса.
- Всё на русском.

## Если что-то не работает

- `Connection refused` — Ollama не запущена. Откройте приложение Ollama или
  выполните `ollama serve`.
- Первый ответ идёт минуту — это загрузка модели, дальше быстрее.
- `статья не найдена` при скачивании — Википедия ограничивает частоту
  запросов; подождите и запустите `fetch_data.py` ещё раз (готовые файлы
  пропускаются).
- Предупреждение про LibreSSL — особенность системного Python на macOS;
  для запросов к localhost оно безопасно и подавлено в `ollama_client.py`.
